## 1. 现场用途

云端最实用的工作是发现整场失联、场地扫描停滞和大范围掉算力，并及时通知值班人员。
场地断电时，本地监控本身可能停止；这时云端通知是否可靠，比多显示一项数字更影响处置。

| 功能 | 实用性与边界 |
|---|---|
| 全网与各场地摘要、趋势 | 适合老板和值班经理找出异常场地。采样新鲜度、数据缺失和部分合计必须保留区别。 |
| 客户实时、周期平均、耗电估算 | 适合趋势对照和初步核对；客户由矿工名归组，监控估算不等于电表或合同结算。 |
| 主动上报与 AMC1 接入 | 地址与 token 等信息放在一份接入包中，场地网页/命令界面整段粘贴。AMC1 是编码，不是加密。 |
| 失联/停滞/骤降/掉线规模通知 | 核心能力。本次重点验证触发、恢复、服务商确认、失败补发及配置变化。 |
| 撤销、删除、恢复场地 | 有实际用途，应按场地 ID 操作。删除会丢掉对应历史，恢复记录后需生成新接入信息。 |
| viewer / admin | 当前是全网角色权限。viewer 能读所有场地和客户分组，不是客户隔离门户。 |
| 多语言、日间/夜间 | 有助于不同值班环境，属于使用便利性，不增加故障处理步骤。 |

依据：`server.py`、`collector.py`、`notify.py`、`auth.py`、`db.py` 和对应测试。
已有采样、功率、电量、平均算力与跨场地口径见 [数据逻辑审计](DATA_LOGIC_AUDIT.md)。

## 2. 本次复现并修复的通知缺陷

### A. 算力没有恢复，滚动基线却让告警消失

最小反例：算力从 100 降到 50 后持续不变。原程序使用 45～90 分钟前的滚动均值做恢复判断；
当历史窗口也降到 50 时，会错误通知“恢复”，尽管实际仍只有原算力的一半。

现在每次骤降事件保留触发时的原始基线。恢复阈值一直对照该基线，缺测不触发恢复。
例如骤降阈值 30%，原基线 100，恢复需回升至 85，而不是随着低算力持续时间自动降低要求。

### B. 首次发送失败后不再尝试

原程序在发送前就占用冷却记录，并推进状态；如果失联通知恰好网络失败，持续失联期间没有新状态跳变，
该通知会永久丢失。

现在当前事件的未送达通道进入内存重试队列，间隔为 60、120、240、480 秒，之后最高 900 秒；
由采集循环在到期后执行，循环延迟也会使实际发送推迟。成功通道不重复补发，每个通道独立记录结果。
恢复或相反状态会取消过期消息，删除场地会清理待发事件。
关闭通知表示暂停投递；重新启用时，对仍成立且尚未送达的当前事件继续处理，不补发已经恢复的旧故障。

队列按场地和三类事件组限制，不无限累积历史消息。它保存在进程内，服务重启会丢失未送达队列；
现有启动首轮只建立状态基线的策略仍保留，没有宣称提供重启后可靠投递。

### C. HTTP 可达被当成业务发送成功

原程序只看 HTTP 返回是否成功。企业微信/钉钉 HTTP 200 但 JSON `errcode` 非零时，测试仍可能显示成功。

现在 Telegram 要求 JSON `ok` 为 true，企业微信/钉钉要求整数 `errcode` 为 0；
重定向和业务错误不算成功。自定义 raw Webhook 维持 HTTP 2xx 接收契约，可以返回空响应体。
服务商确认接收也不等于某个值班人员已经阅读消息。

## 3. 运维说明修正

部署文档原先将云端数据描述为“可以重新积累，不算关键”。实际历史、通知记录、改名、删除记录及凭据
不能靠下一次上报全部恢复。本次改为数据库在线备份，并明确保存配置覆盖层与所用证书/私钥。
没有新增需要用户逐项配置的通知表单。

## 4. 验证及限制

测试使用内存 SQLite、模拟时钟和模拟通道，不发送真实 Telegram、Webhook 或邮件。
持续低算力的误恢复反例使用真实历史序列；补发测试包括多个通道部分成功、退避、冷却、
相反状态、场地删除、关闭/重开及业务错误码。

本轮完整测试：**279 项通过、6 个子测试通过**；其中新增通知专项 **49 项**。
暂停期间恢复、随后再次故障、仅恢复以及双通道部分成功另经独立反例复核。

```bash
python -m pytest -q
```

专项文件：`tests/test_notify_delivery.py`；已有数据、鉴权、接入、删除、客户统计与网页回归均包含在全量套件内。
真实服务商可达性、机器人群配置、生产设备固件和现场电表未在本轮访问或验收。

实现协议参考：[Telegram Bot API — Making requests](https://core.telegram.org/bots/api#making-requests)。
企业微信与钉钉官方页面在本轮检索中未能完整读取；回归测试验证上述返回值处理契约，不能替代实际通道验收。

## 5. 2026-11-04：配置完整性与通知重启恢复

本轮修复基线为 `5aa88590330528490213bd43ae566d9e14faa9c6`。

### 安全配置不再静默回退

`cloud_settings.json` 的坏 JSON、错误节点类型和读取权限错误均属于配置异常。
进程仅能回退到曾成功读取的完整覆盖层，保留已经修改的口令与已撤销的场地 token。
首次文件不存在产生的空值不算可信覆盖层；之后遇到坏文件时，认证失败关闭。
新进程遇到已有坏文件或不可读文件时停止启动，修复内容或属主权限后再启动。

完全不存在的文件在全新进程中仍按首次安装处理；当前没有额外的持久化初始化标记。
因此不要通过删除覆盖层来处理配置错误，备份与恢复须包含该文件。

### 通知设置先保存，成功后生效

同一配置锁覆盖复制、校验、持久化和原地应用全过程。写盘失败时，运行中的通知开关、
通道地址和密钥保持原值，不记录虚假的保存成功审计。原地应用保留 Notifier 捕获的字典引用；
空白密钥仍表示保留旧值。首次 alerts 为缺失、空对象或 YAML null 的情况也有回归覆盖。

### 重启后继续未送达通道

`notification_state`、`notification_outbox`、`notification_cooldown` 三张 SQLite 表保存活动事件、
原始算力基线、每个通道的回执、重试退避和成功冷却。事件先落库再发送，每个成功通道立即保存回执，
不等待其他通道完成。旧数据库通过增量建表和加列迁移，保留历史与场地管理记录。

重启后先对照当前状态与采样有效性：故障仍成立时继续未送达通道；故障已恢复则取消旧消息；
缺测不算恢复，但暂停发送缺少新证据的测量告警。每轮最多执行 20 个通道请求，超过部分留待后续轮次。
删除场地同时清除通知检查点并增加删除代次，删除前已经在途的旧实例不能复活删除或恢复前的事件。

供应商接收请求与 SQLite 保存回执无法组成原子事务。如果进程恰在供应商接收后、本地回执提交前
被强制终止，仍可能重试一次；已经落库的成功通道不会因重启而重复发送。
首次从没有检查点的旧版本升级时，第一轮只建立基线，避免集中通知全部既存故障。

### 前端请求时序

总览趋势、场地详情与日报绑定当前请求序号；切换周期、关闭重开相同场地、A→B→A 时，
旧响应和已关闭详情的旧错误不能覆盖当前内容。

回归包含真实 SQLite 关闭重开、部分通道成功、发送中途退出、冷却与退避恢复、删除/恢复、旧库迁移、
磁盘失败时禁止发送，以及执行实际 UI 函数的乱序请求。全部外部通知通道均使用测试替身。

```bash
python -m pytest -q
node tests/data_quality_behavior.cjs
```

专项文件：`tests/test_settings_integrity.py`、`tests/test_notify_restart.py`、`tests/data_quality_behavior.cjs`。
GitHub 的 Regression tests 工作流覆盖 Python 3.8、3.12、3.14 和 Node 前端行为回归。

### Git 更新与失败恢复

云端先检查工作区是否干净，并在独立目录验证候选代码的语法、导入与启动钩子。
依赖变化时建立独立环境，保持当前环境可回退。候选检查失败不切换运行代码；切换前再次检查 HEAD 与现场改动，
更新状态先落盘，API、自动更新和 CLI 使用进程锁与文件锁串行化。

启动器保留恢复代码，要求新实例运行至少 60 秒并通过真实 HTTP 健康检查。实例随机标识防止旧监听器误确认；
HTTP 与自签 HTTPS 均经过实际服务进程验证。候选意外退出（包括退出码 0）或启动超过 180 秒计为失败，
三次失败后恢复上一代码与解释器；明确收到停止信号时不误计失败。工作区有新改动时停止自动回退，保留现场。

旧 `python server.py` / systemd 入口兼容转入启动器，非 Git 源码包和 Docker 启动路径保留。
已有受保护 Git 安装的安装/更新脚本复用同一更新流程，保持代码与活跃解释器一致，并继续支持离线 wheels。
详细边界与首次从旧版本升级的说明见 [部署与更新](DEPLOY.md#6-更新与发布git-更新器)。

专项文件：`tests/test_updater_safety.py`、`tests/test_install_source.py`。测试使用临时 Git 仓库和真实子进程，
覆盖脏工作区、依赖失败、合法语法的导入/启动错误、重复更新、失败提交跳过、无响应子进程及回退保护。
