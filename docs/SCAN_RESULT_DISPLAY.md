# 扫描结果显示与统计清理

更新日期：2026-11-04。云端基线 `8a19ac2e2082d8bc2078d4aac4189e65069dc5fe`。

## 最近完成扫描

场地扫描下一轮时，云端卡片、客户实时算力和算力趋势显示上一轮完成结果。
正常推进的长扫描不会因为先读到的矿机超过15分钟而把几百台在线机器变成0或空值。
下一轮完成后统一更新；实际确认的0仍显示0，缺少数据仍显示 `—`。

上报/拉取协议可携带 `scanning` 和原始 `scan_progress_ts`。
云端只接受经源时钟校验的进度，收到HTTP请求本身不会刷新该心跳。
真正失联、失败或进度停止仍产生状态提示，曲线相应保留缺口。
`scan_started_ts` 对应已经完成的 `scan_ts`，不是正在执行那一轮的开始时间。

显示接口增加 `display_totals`、`display_metrics`、客户 `display_hashrate_ths` 与趋势显示字段，
前端在新字段存在时优先使用，显式null不会回退到旧值。显示趋势每时间桶采用最后完成结果，
不是时段平均。严格测量通道、通知基线与日报积分继续使用原始时间，不因保留显示而增加耗电。

## 自动清理

首次启动时，若存在不兼容统计，先用SQLite备份API保存包含WAL提交的数据，再事务性清理：

- 旧 `daily` 估算日报；
- 没有时间/完整性证据的旧成功摘要；
- 客户报表中的旧估算列，以及没有合法统计时间范围的累计/平均值。

有效摘要、当前客户名单、有效日报/统计、场地注册、自定义名称、删除代次、客户排序水位、
通知队列/成功回执/冷却状态与审计全部保留。`config.yaml`、`cloud_settings.json`、证书及其他配置文件不写入、不删除。

备份位于数据库同目录，文件名 `<数据库名>.before-statistics-cleanup-<随机后缀>.sqlite3`，
权限为0600，并已加入Git忽略规则。备份失败时不清理，清理事务中途失败整体回滚。
成功后保存迁移标记，重复启动不再清理或创建备份。正常接入也不再把旧协议估算恢复成当前数值。

## 页面和历史

客户表和日报只显示正常数值或 `—`；移除“旧口径记录”详情、旧统计曲线及重复的迁移说明。
必要的缺测或采样信息使用简短悬停提示，实际故障、离线和失联状态继续显示。
缺少可信历史的时段不制造电量，新采集结果按现有统计窗口继续累计。
